Tracking and marketing automation for a WooCommerce store, built on User.com

A full SaaS implementation done solo in about a week: product-event tracking through Google Tag Manager, three automations, and a webhook integration with Google Sheets.

Product-event trackingProduct views and add-to-cart sent to User.com with name, ID, price and image URL.
Newsletter flowPop-up 10 seconds into a first visit, contact created on sign-up, thank-you email sent automatically.
Abandoned-cart recoveryEmail that renders the exact product left in the cart, pulled from the contact's last event.
Sheets integrationEmail opens and product views written to Google Sheets through a webhook and an Apps Script endpoint.
Own idea: interest signalContacts who view a product are tagged and flagged in the sheet, so sales can reach out before the cart stage.

1. Tracking product events

WooCommerce did not expose product data in the data layer, so I read it from the page. A Custom HTML tag fires on DOM Ready on product URLs, takes the name, price, product ID and main image from the DOM, normalises the price (99,99 zł → 99.99) and pushes a product_view event. A second tag sends it to User.com as a standard product event.

// User.com SDK loads asynchronously, so the tag retries instead of losing the event
var tries = 0;
function fire() {
  if (typeof userengage === 'function') {
    userengage('product_event', data);
  } else if (tries < 20) {
    tries++;
    setTimeout(fire, 300);   // up to ~6 s
  }
}
fire();

2. Automations

The newsletter flow waits 10 seconds on a first visit, shows a pop-up and sends a thank-you email once the form is filled. The abandoned-cart flow starts on an add to cart event, waits, sends the recovery email, and on Opened calls my Apps Script endpoint so the open lands in Google Sheets.

3. The recovery email

The email uses User.com snippet tags to loop over the contact's most recent add to cart event and render that product's name, price and image, so each person sees what they actually left behind.

What I would add in production

  • A secret token in the webhook, validated by the Apps Script endpoint.
  • Throttling on the interest signal, so a page refresh does not create a new alert.
  • Numeric lead scoring instead of a single tag, with an alert to sales above a threshold.
  • Product data from a native data layer instead of DOM scraping, which breaks when the theme changes.
